## CLAIM ≠ PROOF

AI can generate an answer.

V3XILITE is being built for the harder problem: **knowing what happened, what was allowed, what evidence supports it, and whether the result can be trusted.**

```text
INTENT → MISSION → ACTION → VERIFY → PROOF
```

V3XILITE is a developing ecosystem for personal intelligence, verifiable AI workflows, research, code, operations and controlled automation.

It is not designed around giving an AI unlimited authority. It separates **intelligence from permission**, **action from evidence**, and **confidence from proof**.

> **Trust is architecture.**

# V3XILITE Proof

### Intelligence built around evidence, verification and control.

V3XILITE Proof is the trust foundation of the ecosystem.

Its central principle is simple:

> **An AI being capable of doing something does not mean it should automatically be allowed to do it.**

Proof is being developed to understand requests, preserve useful context, enforce authority boundaries, coordinate work and produce evidence about what actually happened.

### Public capability areas

**Personal intelligence**
- Personal command center
- Today / Needs You / Continue workflows
- Private notes and continuity
- Persistent and temporary conversations
- Search and context-aware work

**Projects**
- Isolated project context
- Project intelligence
- Reusable project knowledge
- Decisions and activity history
- Collaboration without silently merging authority between users

**Collaboration**
- Comments and mentions
- Decision states
- Notifications
- Traceability
- Separation between personal and shared context

**Missions**
- Intent translated into bounded work
- Multi-step execution
- Approval points
- Resumable workflows
- Verification before completion

**Intelligence fabric**
- Multiple intelligence providers behind a unified experience
- Capability-based routing
- Different reasoning depths for different workloads
- Provider choice treated as infrastructure, not the product

**Authority**
- Identity and permission checks
- Scope-aware actions
- Risk-sensitive confirmation
- Stronger authentication for critical effects
- No model receives authority simply because it generated a response

**Evidence**
- Provenance
- Verification
- Receipts
- Separation of facts, inference and unsupported claims
- Audit-oriented history for important effects

## Proof Receipts

A successful action should not end with only:

> “Done.”

It should be possible to establish:

- what was requested;
- who or what was authorized;
- what scope applied;
- what changed;
- what evidence was produced;
- what verification passed;
- and what the result can actually prove.

That is the direction behind **Proof Receipts**.

The goal is not more logs. The goal is evidence with meaning.

# V3RA

### Personal Intelligence Runtime.

V3RA is the premium, local-first intelligence system being developed alongside V3XILITE Proof.

It is intentionally not positioned as another chat interface.

> **V3RA does not execute commands. V3RA reconciles reality with intent.**

V3RA is designed to reason about goals, context, constraints, tools and changing state while keeping authority outside the model itself.

### Local-first intelligence

- Keep useful intelligence close to the user when practical
- Specialized model capabilities
- Selective activation instead of treating every request as the same workload
- Resource-aware execution
- External intelligence under policy rather than as an invisible default

### Governed memory

- Personal continuity
- Project memory
- Controlled retrieval
- Context that does not automatically become permission

### Internal challenge

V3RA explores separated roles for creating and challenging work:

```text
BUILDER → BREAKER → REVIEWER → JUDGE
```

The objective is not to make one model appear more confident. It is to create disagreement, verification and stronger decision boundaries.

### Controlled evolution

V3RA is being developed around a path for safely extending capability:

- Capability discovery
- Isolated evaluation
- Skill synthesis
- Adversarial testing
- Verification before trust

The goal is to improve what V3RA can do **without allowing it to silently rewrite the rules that govern it**.

### Tools and missions

- Permission-aware tools
- Bounded actions
- Dry-runs and isolation where appropriate
- Mission-level verification
- Human confirmation for sensitive effects

### Presence

The long-term interface extends beyond text toward voice, presence, devices, services and multiple controlled channels.

The interface can evolve. The authority model remains separate.

# Trust Fabric

V3XILITE is being built around several non-negotiable ideas.

### Authority before capability
Being technically capable of an action is not authorization to perform it.

### Evidence before confidence
A confident model output is not proof.

### Scope matters
Identity, project, user, device and mission boundaries should remain explicit.

### Critical actions require stronger confirmation
Higher-risk effects can require fresh user authentication and explicit approval.

### Intelligence is replaceable
Models and providers can change. The trust model should not depend on one model staying the same forever.

> **The intelligence can change. V3X doesn't.**

### Local-first where it matters
Private context, personal intelligence and sensitive processing should stay local when practical, with external capabilities treated as governed dependencies.

### Human sovereignty
The user remains the final authority for actions that meaningfully affect their data, infrastructure, accounts or devices.

---

# Privacy by design

Privacy is not intended to be a settings page added at the end.

The ecosystem is being designed around data minimization, project and user isolation, explicit permissions, private memory boundaries, scoped access, secret separation, ephemeral use where appropriate and local-first processing where practical.

Future work includes a broader **Privacy Gateway / Vault** model for sensitive data.

---

# Security direction

V3XILITE is being developed with defensive security as part of the architecture rather than as a cosmetic claim.

Public areas include passkey-oriented authentication, server-side authorization, scoped permissions, isolation, anti-replay concepts, evidence preservation, controlled tool execution, post-execution verification and sandboxed capability evaluation.

V3RA also includes research into defensive recovery and binary-analysis workflows for systems the user owns or is explicitly authorized to analyze.

Operational security details, detection logic, policies and attack-surface information are intentionally not published.

See [SECURITY.md](SECURITY.md).

---

# Designed for outcomes, not apps

V3XILITE is not intended to become a collection of disconnected buttons for different services.

The longer-term direction is to organize intelligence around **intent, effects and verified outcomes**.

A user should be able to express what they want accomplished while the system determines relevant context, available authority, required approvals, appropriate tools, possible simulation, necessary evidence and what counts as completion — without removing the user's control.
