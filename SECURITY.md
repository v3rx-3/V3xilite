# Security Policy

Security is part of the V3XILITE product architecture.

## Reporting a vulnerability

If you believe you have found a security issue affecting an official V3XILITE system, **do not publish exploit details in a public GitHub issue**.

Please use the private contact channel provided through the official V3XILITE website:

https://v3xilite-tech.v3xilitetech.workers.dev/

When reporting an issue, include enough information for us to understand and reproduce the problem without accessing data or systems you are not authorized to test.

Useful information includes:

- affected V3XILITE product or surface;
- concise description;
- reproduction conditions;
- expected vs. observed behavior;
- potential impact;
- supporting evidence with secrets and personal data removed.

## Scope and authorization

Testing must be limited to systems and accounts you own or have explicit authorization to assess.

Do not:

- access another person's data;
- degrade availability;
- use social engineering;
- exfiltrate secrets;
- establish persistence;
- perform destructive testing;
- publish sensitive vulnerability details before remediation.

## Disclosure

We value responsible security research. Coordinated disclosure gives the project an opportunity to validate and remediate legitimate issues before technical details become public.

## Architecture

This public repository does not contain the production source tree, security rules, private prompts, credentials, detection logic or internal infrastructure.

Security-sensitive implementation details are intentionally private.
