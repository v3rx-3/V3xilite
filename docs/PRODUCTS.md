# V3XILITE — Products

V3XILITE is being developed as an ecosystem of intelligence, trust and execution systems.

This document intentionally describes **product boundaries and public direction**, not proprietary implementation.

## V3XILITE Proof

**The trust, evidence and control foundation.**

Proof is designed around a simple distinction: producing an answer, performing an action and proving an outcome are different things.

Public product areas include personal intelligence, conversations, projects, collaboration, decisions, missions, controlled multi-provider intelligence, identity, permissions, evidence and Proof Receipts.

### The public promise

V3XILITE Proof is being built to make important AI-assisted work more inspectable:

- what was requested;
- what context was used;
- what authority existed;
- what action was performed;
- what evidence was produced;
- what verification passed;
- and what the final result can legitimately claim.

Internal policies, prompts, routing, security mechanisms and architecture remain private.

---

## V3RA

**Personal Intelligence Runtime.**

V3RA is a separate local-first intelligence runtime designed to coordinate reasoning, memory, tools and missions under explicit authority boundaries.

Its direction includes:

- local-first intelligence;
- resource-aware execution;
- specialized expert capabilities;
- governed personal and project memory;
- permission-aware tools;
- mission execution;
- verification;
- controlled capability evolution;
- optional external intelligence under policy.

V3RA is not intended to gain authority simply because it can reason about an action.

### Internal challenge

Publicly, V3RA can be understood as using separated creation and verification responsibilities:

```
BUILDER → BREAKER → REVIEWER → JUDGE
```

The implementation behind those roles is proprietary.

---

## V3X Research

Research with sources, provenance, freshness, contradiction handling and reusable evidence.

The goal is to move from “search and summarize” toward research missions whose results can be inspected and reused.

---

## V3X Code

A controlled software-change environment.

The product direction includes isolated change spaces, planning, tests, adversarial review, approval and evidence before meaningful changes are applied.

V3X Code is not publicly released through this repository.

---

## V3X Operations

The execution layer for governed operations.

Rather than exposing unrestricted infrastructure control to a model, the direction is mission-oriented execution with desired state, scoped authority, dry-runs, approvals, verification and receipts.

---

## V3X Control

The human control surface for interacting with V3RA, missions, devices and services while preserving the same authority model.

---

## Shared foundation

Across the ecosystem:

```
INTELLIGENCE ≠ AUTHORITY
ACTION ≠ PROOF
CONTEXT ≠ PERMISSION
```

Models, providers and interfaces may change.

The trust boundary should survive those changes.
